# Continents 개인 사용 개선 구성

제공된 `Continents_v1.2.1+26.3.zip`을 기준으로 제작했습니다. 원본 ZIP과 원작자 표시, 라이선스, 지원 포맷 `[121, 0]`은 유지합니다.

추가 필수 조건: 대양은 서로 연결되고 고립된 내해가 없어야 하며 작은 호수는 허용합니다. 이 조건을 위한 새 결과물은 `output/Continents-Connected-Ocean-26.3.zip`입니다. 이전 세 프리셋 대신 이 ZIP 하나를 사용합니다. 생성 구조와 검증 한계는 `CONNECTED-OCEAN.ko.md`를 참고하세요.

## 개선 사항

- 기존 설정 도구의 오래된 `argument1/argument2/argument` 경로를 실제 데이터의 `left/right/input` 경로로 수정했습니다. 대륙 크기, 시작 섬 크기, 주변 섬 크기 설정에 적용됩니다.
- 설정 화면의 제목, 항목명, 설명을 한국어로 정리했습니다.
- 기본 월드와 큰 생물 군계 모두에 같은 비율의 조정을 적용했습니다.
- 원본을 매번 다시 읽어 변경이 중첩되지 않는 빌드 도구와 변경 전후 값·SHA256 검증 기록을 제공합니다.

## 프리셋

수치는 원본 대비 설정 비율입니다. 실제 육지 비율이나 생성 섬 개수를 보장하는 수치가 아닙니다. 크기는 기존 설정 도구의 제곱근 변환을 유지합니다.

| 파일 이름의 프리셋 | 대륙 크기 | 시작 섬 크기 | 주변 섬 크기 | 주변 섬 생성 영향 |
| --- | ---: | ---: | ---: | ---: |
| balanced (기본 추천) | 140% | 125% | 120% | 120% |
| archipelago (군도형) | 85% | 140% | 140% | 150% |
| grand (대륙형) | 200% | 150% | 100% | 85% |

지형 변화 방향은 설정 의도이며, 실제 해안선과 시작 위치는 시드에 따라 달라집니다. 시작 섬 확대가 안전한 스폰이나 특정 생물 군계를 보장하지는 않습니다.

## 설치

1. 우선 새 테스트 월드를 준비합니다. 기존 월드를 사용할 경우 서버를 종료하고 백업합니다.
2. `output`의 ZIP 중 하나만 월드의 `datapacks` 폴더에 넣고, 기존 Continents ZIP은 서버 밖으로 옮깁니다. 세 프리셋을 동시에 넣지 않습니다.
3. 서버를 완전히 재시작하고 콘솔의 데이터팩 로딩 오류 및 `/datapack list enabled`를 확인합니다.
4. 새로운 청크에서 지형을 확인합니다. 이미 생성된 청크에는 소급 적용되지 않으며 경계가 생길 수 있습니다.

다른 지형 데이터팩이 동일한 `minecraft` 밀도 함수를 덮어쓰면 충돌할 수 있습니다. 실제 서버에서 함께 사용하는 팩과 확인해야 합니다.

## 재빌드 및 검증

Python 3 표준 라이브러리만 사용합니다. 작업 폴더에서 실행합니다.

```powershell
python continents/build.py
python continents/build.py --source 'C:/Users/Administrator/Downloads/Continents_v1.2.1+26.3.zip'
```

검증은 JSON 파싱, 설정 대상 경로와 숫자 자료형, 설정 범위, 스플라인 좌표 순서, Continents 내부 노이즈·밀도 함수 참조, ZIP 무결성 및 루트 메타데이터를 확인합니다. 변경 내역은 `output/validation.json`에 기록합니다. Minecraft 서버 구동 및 여러 시드의 실제 지형 생성은 검증하지 않았습니다.
