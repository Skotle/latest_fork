# Infernal Difficulties 1.2.0 — Paper 26.3

Peaceful → Easy → Normal → Hard → Harder → Insane → Demon → Nightmare

전투와 생존 요소를 함께 적용하는 단독 플러그인입니다. JAR 하나만 사용하며 데이터팩·의존 플러그인·모드·리소스팩은 필요 없습니다. 기존 바닐라 속성·장비·피해·생존 규칙을 조정하고 새 몹·아이템·스킬·이벤트·공격 패턴은 추가하지 않습니다.

## 설치와 업데이트

서버를 종료하고 이전 InfernalDifficulties JAR을 제거한 뒤 `InfernalDifficulties-1.2.0-Paper-26.3.jar` 하나를 `plugins`에 넣으세요. 기존 설정 폴더와 선택 난이도는 유지합니다. 시작하면 `plugins/InfernalDifficulties/profiles.yml`이 생성됩니다. Java 25 / Paper 26.3용입니다.

```mcfunction
/difficulty
/difficulty peaceful
/difficulty easy
/difficulty normal
/difficulty hard
/difficulty harder
/difficulty insane
/difficulty demon
/difficulty nightmare
```

조회·자동완성·`/execute run difficulty nightmare`를 지원합니다. 권한은 `minecraft.command.difficulty` 또는 기본 OP 전용 `infernal.admin`입니다. `/minecraft:difficulty`는 바닐라 명령으로 남으므로 상위 단계 선택·해제에는 접두사 없는 명령을 사용하세요.

기존 v1/v2 개체는 로딩 시 원본 속성·장비를 복원한 뒤 v3 설정을 한 번 적용합니다. 같은 설정의 재시작·재로딩·재선택에는 중첩·재추첨하지 않습니다. profiles.yml을 편집하고 재시작하면 변경된 단계의 개체가 한 번 갱신됩니다.

## 전투와 장비 적용

- 기존 대상 목록과 Paper의 Enemy 분류를 포함해 적대 몹 전반의 지원 속성에 적용합니다. 일반 동물·주민·아군 골렘·길들인 동물은 제외하고 중립 몹의 적대 조건은 유지합니다. 아기 몹의 이동속도는 더 높이지 않으며 추적 거리 상한은 64블록입니다.
- 드래곤·위더·엘더 가디언·워든은 별도 보스 체력·피해 배율을 사용합니다. 면역·약점·기존 공격 패턴은 유지합니다.
- 몹의 화살·삼지창·화염구·마법·범위 공격·폭발을 기존 피해 이벤트에서 강화합니다. 속성으로 이미 강화한 근접 피해는 다시 곱하지 않고, 보스 피해에는 보스 배율만 한 번 적용합니다. 플레이어가 가한 피해와 발사체는 추가 배율을 적용하지 않습니다.
- 크리퍼 점화 시간은 30/30/25/20틱, 기본 반경 3 기준 폭발 반경은 3/3/4/4입니다. 다른 몹의 폭발 반경은 ×1/×1/×1.15/×1.3입니다. 기존 지형 파괴 범위도 커질 수 있으며 mobGriefing은 유지합니다.
- 출처가 확인되는 몹의 기존 부정 효과는 지속시간만 증가합니다. 효과 단계는 올리지 않습니다. 음식·명령·플레이어·출처 불명 효과는 그대로입니다.
- 방어구 대상은 좀비·허스크·드라운드·좀비 주민·스켈레톤·스트레이·보그드·위더 스켈레톤·피글린·피글린 야수·좀비화 피글린입니다.
- 검·도끼를 쓰는 위 계열과 변명자의 무기를 원래 역할대로 강화합니다. 스켈레톤의 활과 피글린·약탈자의 쇠뇌도 강화합니다. 쇠뇌에는 빠른 장전·관통을 사용하며 다중 발사와 관통을 중첩하지 않습니다. 약탈자·변명자에게 보이지 않는 방어구를 추가하지 않습니다.
- 삼지창 등 다른 무기 역할을 검으로 바꾸지 않습니다. 착용할 수 없는 몹에게 장비를 억지로 주지 않습니다. 기존 강한 장비·인챈트는 보존하며 약한 장비를 교체하면 원본과 드롭 확률을 개체에 저장합니다. 상충하거나 새 장비 종류에 옮길 수 없는 인챈트를 강제로 합치지 않습니다.
- 커스텀 몹은 소환 시 `infernal.exclude` 태그 또는 PDC `infernaldifficulties:exclude` 바이트 1로 제외합니다.

## 생존과 월드 복원

`survival-scaling: true`가 기본입니다. false로 바꾸고 재시작하면 생존 보정만 해제하고 전투 보정은 유지합니다.

허기는 기존 달리기·채굴·전투·회복 등의 탈진 이벤트에 배율을 적용합니다. 자연 회복은 음식·포만감의 SATIATED 회복량만 줄이며 물약·재생·토템 회복과 자연 회복 허용 게임 규칙은 유지합니다. 환경 피해는 낙하·용암·화염·익사·동결·질식·번개·접촉·비행 충돌·떨어지는 블록·출처 없는 환경 폭발 등을 조정합니다. 공허·굶주림·명령 피해는 기본 규칙입니다. 출처 있는 몹·플레이어 공격에는 환경 배율을 중복 적용하지 않습니다.

내구도는 기존 소모 요청에 배율을 적용하고 소수점은 플레이어 PDC에 누적합니다. 매 1 소모를 무조건 2로 올리지 않으며 내구성·수선 자체는 그대로입니다. 생존 보정은 Survival/Adventure 플레이어에만 적용합니다.

생성은 몬스터 상한과 기존 생성 시도 간격을 조정합니다. 간격은 최소 1틱이므로 기본값이 이미 1틱이면 빨라지지 않습니다. 상한 70 기준으로 77/88/105/123이 됩니다. 생성 중지 0과 기존 밝기·지형·스포너·디스폰·게임 규칙은 존중하며 추가 몹을 직접 소환하지 않습니다. 동물 등 다른 생성 분류는 변경하지 않습니다. 실제 출현 수는 플레이어·청크·서버 설정에 따라 달라집니다.

수면은 기존 설정보다 쉬워지지 않도록 최소 비율을 적용합니다. Nightmare 101%에서는 잠으로 밤을 넘기지 못하지만 침대의 부활 지점 설정은 가능합니다. 낮·밤 길이와 날씨는 유지합니다. 생성·수면 원본은 월드 PDC에 저장하며 일반 단계로 돌아가거나 정상 종료할 때 복원합니다. 재시작 시 저장된 난이도를 다시 적용해 상한이 중첩되지 않습니다. 다른 도구가 같은 설정을 동시에 변경하면 복원 시 저장한 원본으로 돌아갑니다.

## 드롭과 바닐라 위임 항목

일반 전리품은 기존 드롭 테이블 그대로입니다. 지급·강화 장비는 드롭 확률 0과 사망 드롭 필터를 적용합니다. 교체 전 장비를 사망 시 따로 지급하지 않습니다. 경험치는 강화 전 장비 기준으로 계산합니다.

주민 감염·좀비 문 파괴·증원·지역 난이도·거미 효과·습격 웨이브는 기반 난이도 규칙에 위임합니다. Hard에서 이미 상한인 항목은 상위 단계도 Hard 규칙입니다. 습격 몹에는 선택 단계의 전투 보정을 적용합니다.

제작·광물·농작물·거래·음식 회복량·플레이어 최대 체력·인챈트 상한·일반 드롭·사망 아이템/경험치·keepInventory·하드코어·부활·방패·토템·PvP 설정은 기존 월드 규칙을 상속합니다. 개인 생존 부담은 PvP 중에도 같은 난이도를 따릅니다. 전체 Minecraft 시스템을 교체하는 모드는 아닙니다.

## 전환·제거·검증

기존 데이터팩을 설치했다면 데이터팩 활성 상태에서 `/function infernal:set/hard`를 실행하고 강화 지역을 로딩해 복원한 뒤 서버를 종료하고 ZIP을 제거하세요. 두 구현을 동시에 사용하지 않습니다. 데이터팩의 `inf.active` 태그가 남은 개체는 중첩 방지를 위해 제외합니다.

플러그인 제거 전에는 `/difficulty hard`로 복원하고 강화 몹이 있는 지역을 로딩하세요. 미로딩 청크 개체는 다음 로딩 때 복원되므로 먼저 JAR을 제거하면 그 개체의 강화가 남습니다. 복원이 어렵다면 적용 전 백업을 사용하거나 Hard 상태로 플러그인을 유지하세요. 생성·수면 정책은 정상 종료에도 복원됩니다.

```powershell
python infernal-paper/build.py
python infernal-paper/verify.py
```

격리된 실제 Paper 서버를 두 번 실행해 1,600마리 무장 표본, 장비·점화·반경 복원, 프로필 갱신, 명령·권한·재시작과 월드 정책을 검사합니다. 생존 수치 검사는 실제 Paper 이벤트 객체·플레이어 대역과 월드에 등록한 실제 서버 플레이어 개체를 사용합니다. 실제 플레이어 경로에서도 탈진·회복·독 시간·우유 해제를 확인하며 클라이언트 접속 테스트는 아닙니다. 정확한 서버 버전·항목별 결과·JAR SHA-256은 `output/validation.json`에 기록합니다. 실제 전투 체감과 클라이언트 화면은 별도 플레이 테스트 대상입니다.
