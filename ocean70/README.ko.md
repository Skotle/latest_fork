# 다대륙·대해양 월드젠 — Ocean70 / Land30

Minecraft **Java Edition 26.3**, 일반 오버월드(`minecraft:normal`)용 데이터팩입니다. 원점 중심 **10,000×10,000 블록**에서 평균 육지 약 30%, 해양 약 70%를 목표로 합니다. 대륙 사이에는 굽이치는 깊은 바다가 이어지고, 대륙 주변에는 작은 섬과 자연 해안이 생성됩니다.

## 설치

1. `output/Ocean70-Land30-Java-26.3.zip`을 사용합니다. ZIP은 풀지 않습니다.
2. 싱글플레이: **새 월드 만들기 → 데이터팩**에서 ZIP을 추가한 뒤 **일반** 월드를 생성합니다.
3. 서버: 종료한 상태에서 새 월드의 `<월드명>/datapacks/`에 ZIP을 넣고 시작합니다. `level-type=minecraft:normal`을 사용합니다.
4. 게임에서 `/datapack list enabled`로 활성화를 확인합니다.
5. 플레이 범위를 10,000블록으로 제한하려면 관리자 권한으로 다음을 실행합니다.

```mcfunction
/function ocean70:border_10000
```

이 선택적 함수는 오버월드 경계를 `(0, 0)` 중심, 지름 10,000블록으로 설정합니다. 설치만으로 경계가 변경되지는 않습니다. 지형 설정 자체는 경계 밖에서도 계속 적용됩니다.

기존 월드에서는 새로 생성하는 청크에 적용됩니다. 일관된 해안과 통계 검증을 위해 새 월드를 권장합니다. 이미 생성된 지형은 바뀌지 않습니다. 테스트 지도에 사용한 시드는 **73102631**, 다른 예시 시드는 **42**입니다.

## 대륙 크기 제한

대륙 노이즈에 **끊기지 않는 해양 분리망**을 결합합니다. 분리망의 좌표는 시드별 노이즈로 부드럽게 휘어집니다. 강제로 경계를 만드는 명령이나 매 틱 실행 함수는 없습니다.

- 기본 셀 간격: **2,400블록**.
- 각 방향의 최대 수로 굴곡: **256블록**.
- 설계상 같은 셀의 대륙 범위는 각 축에서 **2,912블록 미만**(`2400 + 2×256`)입니다.
- 이 범위를 사각형으로 보수적으로 환산하면 최대 **8,479,744블록²**, 10,000×10,000 범위의 **8.48%**입니다. 실제 대륙은 바다·해안·내륙 수역이 차지하는 부분 때문에 더 작습니다.

이 상한은 분리망으로 나뉜 대륙 생성 필드의 범위입니다. 실제 검증은 16블록 간격의 연결성 표본으로 확인합니다. 플레이어가 만든 다리나 다른 데이터팩의 구조물까지 포함한 모든 블록의 연결성을 보장하는 값은 아닙니다.

## 비율과 검증 기준

`output/engine-validation.json`에 실제 공식 서버 엔진의 측정 결과가 있습니다. 각 시드에서 `x,z ∈ [-5000,5000)`의 청크 중심 **390,625개**를 검사합니다. 해양은 Y=64 바이옴이 `#minecraft:is_ocean`에 속하는 표본이며, 나머지는 육지 범주입니다. 강·호수·해안의 수면 피복률은 이 바이옴 비율과 다릅니다.

8개 시드로 대륙 노이즈 편향을 보정하고, 보정에 쓰지 않은 4개 시드를 포함해 총 12개 시드를 검증합니다. 매 시드나 임의의 이동된 10,000블록 구간에서 비율이 정확히 30:70이 되는 것은 아닙니다.

연결성은 대각선을 포함한 8방향으로 계산하며, 전체 육지 덩어리의 최대 길이와 가장 큰 덩어리의 면적을 기록합니다. 추가로 시드 73102631의 지형 기둥 3,844개를 검사하고 깊은 바다가 해수면 위로 올라오지 않는지 확인합니다. 100만 청크를 실제 디스크에 생성하는 검사는 아닙니다.

지도: `output/biomes-seed-73102631.png`, `output/biomes-seed-42.png`. 픽셀 하나는 청크 중심 표본 하나입니다. 파란색은 바다, 초록색은 일반 육지, 베이지색은 사막·해안, 밝은색은 눈 지형이며, 육지 내부의 하늘색 선은 강입니다.

## 설정 조정과 재빌드

`settings.json`을 편집합니다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `target_ocean_fraction` | 0.7 | 목표 해양 비율 |
| `continent_cell_blocks` | 2400 | 대륙 분리 셀 간격 |
| `maximum_warp_blocks` | 256 | 수로 굴곡의 엄격한 최대 폭 |
| `warp_noise_strength` | 2.5 | 수로가 휘어지는 정도 |
| `ocean_channel_half_width_blocks` | 192 | 수로·해안 형태를 만드는 폭 계수 |
| `coast_transition_blocks` | 256 | 깊은 수로에서 해안까지의 변화 계수 |
| `continental_noise_scale` | 0.35 | 대륙 노이즈의 공간 주파수; 커질수록 육지가 잘게 나뉨 |

목표 최대 축 길이를 줄이려면 `continent_cell_blocks + 2×maximum_warp_blocks`를 줄입니다. 폭 계수는 실제 수로 폭과 1:1 관계가 아니며, 시드별 굴곡과 해안 지형의 영향을 받습니다. 셀을 지나치게 작게 하거나 수로를 너무 넓게 하면 목표 육지 비율을 만들 수 없을 수 있습니다.

이 작업 공간에 이미 있는 공식 26.3 서버와 JDK 25를 사용합니다. Python 외의 별도 Python 패키지는 필요하지 않습니다.

```powershell
python ocean70/build.py
python ocean70/verify.py
```

설정이나 생성식이 바뀌면 빌드가 자동으로 재보정합니다. `--calibrate`를 붙이면 강제로 다시 보정합니다. 설정을 바꾼 뒤에는 새 테스트 월드로 검증합니다.

오버월드의 `minecraft:overworld/continents` 밀도 함수를 재정의하므로 같은 함수를 변경하는 월드젠 데이터팩과 함께 사용하면 우선순위에 따라 설정이 덮어써집니다. 큰 바이옴·커스텀 차원은 검증 대상이 아닙니다. 바다의 과도한 버섯섬 생성을 방지하기 위해 대륙성은 [-1,1]로 제한합니다. 네더·엔드 생성 설정은 변경하지 않습니다.

26.3 밀도 함수 형식은 [Mojang 공식 26.3 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)을 참고했고, 필드와 생성 동작은 로컬 공식 서버로 검증했습니다.
